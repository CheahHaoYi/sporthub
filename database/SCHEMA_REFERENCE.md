# Schema reference for backend mappings

All IDs are `BIGINT GENERATED BY DEFAULT AS IDENTITY`. All creation/update timestamps use `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP` unless noted. Monetary values use `NUMERIC(12,2)`; percentage snapshots use `NUMERIC(5,2)`. Text state columns are constrained to the listed values. The following names are the canonical SQL names for JPA `@Table` and `@Column` mappings.

|---|---|---|

## Backend notes

- PostgreSQL `TEXT` columns are intentionally used for bounded business state values; enforce enums in Java as well as SQL.
- `image_url` and `maximum_discount_amount`, optional references, and `cancelled_at` allow SQL NULL.
- Booking age category is derived using `date_of_birth` and the slot's `starts_at`, never accepted as trusted input. Snapshots are persisted on booking/order item records.
- Bookings refer to the profile with both account ID and profile ID. Map both columns or model an equivalent association so Hibernate validation retains the composite FK.
- A product order item references the current product for referential integrity while preserving `description_snapshot`, `sku_snapshot`, and prices if its catalogue name changes.
- Index definitions and their query use are in V7 and the index list in [README.md](README.md).
