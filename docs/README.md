# SportHub documentation

Start with the [architecture overview](../README.md), then follow the beginner quality-engineering lessons in order. Use the operational QA pages when preparing a run and the requirements pages when deciding what the product should do.

## Reading order

1. [Codebase overview and known implementation gaps](quality-engineering/00-codebase-overview.md)
2. [Quality Engineering syllabus](quality-engineering/README.md) — lessons 01–11 cover testing fundamentals, current tests, design, CI and a local runbook.
3. [Test case catalogue](quality-engineering/test-cases/README.md) and [requirements-to-tests matrix](quality-engineering/requirements-to-tests.md).
4. [QA runbooks and strategy](qa/test-plan.md), [automation framework](qa/automation-framework.md), [test data](qa/test-data.md), and [performance testing](qa/performance-testing.md).
5. [Functional requirements](requirements/functional-requirements.md) and [business rules](requirements/business-rules.md), which distinguish confirmed behavior from product intent awaiting decisions.

The quality-engineering lessons are the canonical detailed explanations and case catalogue. `docs/qa/` contains operational guidance and links back to that source; it should not maintain a second detailed case list.
